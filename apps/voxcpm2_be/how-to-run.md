# How to Run the VoxCPM2 Backend

VoxCPM2 requires Python 3.10, 3.11, or 3.12. Python 3.10 is recommended. Commands below are run from `apps/voxcpm2_be`.

## Windows: CPU fallback

```powershell
py -3.10 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip setuptools wheel
python -m pip install -r requirements.txt
$env:VOXCPM_DEVICE='auto'
python -m src.main
```

Standard PyTorch on Windows does not normally expose Radeon GPUs through ROCm. With `VOXCPM_DEVICE=auto`, the backend therefore uses CPU automatically when no supported GPU runtime is detected.

## Ubuntu/Linux: AMD Radeon with ROCm

First confirm that the GPU is supported by the installed ROCm release. Install the ROCm build of PyTorch using the command generated by the official PyTorch installer for your ROCm version, then install the backend without replacing that Torch build:

```bash
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip setuptools wheel
python -m pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/rocm6.4
python -m pip install -r requirements.txt
VOXCPM_DEVICE=auto python -m src.main
```

The ROCm wheel index changes over time. Replace `rocm6.4` with the version recommended by the current PyTorch installation page. PyTorch exposes ROCm devices through `torch.cuda`; the backend reports `device_backend: rocm` when detected. If accelerated model loading fails, it retries on CPU.

## NVIDIA CUDA

Install the PyTorch CUDA build recommended for the installed driver, install `requirements.txt`, and run with `VOXCPM_DEVICE=auto` or `VOXCPM_DEVICE=cuda`.

## Server configuration

```text
VOXCPM_HOST=127.0.0.1
VOXCPM_PORT=8011
VOXCPM_MODEL_ID=openbmb/VoxCPM2
VOXCPM_DEVICE=auto
VOXCPM_LOAD_DENOISER=false
VOXCPM_OPTIMIZE=true
```

Use `VOXCPM_HOST=0.0.0.0` only when serving another trusted machine on the LAN, and restrict port `8011` with the firewall. This API has no authentication and must not be exposed directly to the public internet.

Health check: `http://127.0.0.1:8011/health`.

The first job downloads approximately 5 GB of model assets from Hugging Face and initializes the model. CPU generation is supported but can be substantially slower than GPU generation.
